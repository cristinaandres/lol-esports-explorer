Two failure modes in `pipeline/refresh-data.sh`, both verified against fixture tags:

1. **Remove-before-copy guts `data/model/`.** With `set -e`, the `rm -f` of every CSV, the dictionary and the DDL runs first; if the tag does not have the files (a legacy layout, a renamed directory), the following `cp` fails and the repository is left with **0 model files** while `source.json` still names the old pin. Recoverable with `git checkout -- data/model`, but the only message is `cp: cannot stat`.
2. **A mid-pin failure leaves a mixed pin with a misleading next error.** With `event-coverage.jsonl` missing from the tag, the CSVs, `manifest.json`, `game-eras.json` and `event-selection.json` are already written (its source string naming the *new* tag) when `pin()` throws. `source.json` is untouched, so the tree holds a new manifest under an old pin — and the next `data:check` reports `stale: public/data/meta.json`, naming none of it.

Fix: stage everything (clone extracts into a temp tree, or copy before removing), swap or roll back on any failure, and end with a consistency assertion so the script cannot exit 0 on a mixed pin. The `fetched`-date no-op logic is fine and should survive.

Check: a tag missing `data/model/`, and a tag missing one curated file, both leave the tree exactly as it was and say why; re-pinning the current tag stays a no-op.

## What changed

`pipeline/refresh-data.sh` now stages the whole pin in `$tmp` before it writes
anything. The tag is cloned, checked for the six files a pin needs (`data/model/`
with its CSVs, dictionary and DDL, `data/curated/manifest.json`, the two curated
JSONL, `tools/dataset/rules/game-eras.json`) and for a model directory of plain
files only, then copied and rewrapped into `$tmp/stage`, where the pin is verified.
A tag that cannot be pinned therefore never reaches `data/`; each layout failure
names the file it could not find and prints `note: nothing was written; data/ and
pipeline/source.json are unchanged`.

After that gate, a snapshot of everything the run owns — `data/model/` whole, the
four upstream copies and `pipeline/source.json` — is taken and verified against the
tree, and the staged files are installed one rename at a time, `source.json` last.
Any failure after the first write rolls back from that snapshot, which is the
previous pin rather than the staged tree, so a dirty tree is restored dirty and a
failed run leaves `data/` byte for byte as it was.

The run ends with a consistency assertion it cannot exit 0 without: `source.json`
names the tag and commit just cloned and records the sha256 of the manifest on disk
(the comparison `build.py` makes), `data/model/` holds exactly the tag's file names
with the tag's bytes, and the four upstream copies are the tag's with each wrapper
naming the tag as its source. The model check compares names as well as bytes,
because a file left over from the previous tag is precisely the defect here and
`git status` cannot see it — an unchanged file is not a diff.

The `fetched` no-op logic, the JSONL wrapper bytes, `set -euo pipefail` and the
usage error (exit 2) are unchanged. One new knob: `REFRESH_SOURCE` names the
repository to clone, defaulting to upstream, so a mirror or a fixture can stand in
without editing the script (the wrapper and `source.json` still name the canonical
repository). It earns its place by making the script testable as committed.

## Verified

Fixture tags in a local repository built from the v1.1.0 tree, cloned through
`REFRESH_SOURCE`:

| fixture | exit | message | `git status --porcelain data/ public/data/ pipeline/source.json` |
|---|---|---|---|
| `no-model` (no `data/model/`) | 1 | `tag no-model has no data/model/` | empty |
| `no-coverage` (no `data/curated/event-coverage.jsonl`) | 1 | `tag no-coverage has no data/curated/event-coverage.jsonl` | empty |
| `changed-record` (one selection record changed) | 0 | `verified: data/ holds changed-record (...) and pipeline/source.json names it` | the changed wrapper + `source.json` |

For both failures every file under `data/` and `pipeline/source.json` hashes to what
it hashed before the run. Two further checks, both on a scratch copy of the tree: a
mid-install failure forced by making `pipeline/` read-only fails on `source.json`
after the model and the four upstream files were already replaced, and still
restores `data/` byte for byte; and disabling the stale-model-file removal makes the
assertion catch the leftover (`data/model/dim_nation.csv is not in tag ...`) and roll
back. A tag that does not exist clones to `cannot clone tag v9.9.9 from ...`.

Re-pinning the current tag against GitHub, `bash pipeline/refresh-data.sh v1.1.0`,
exits 0 with `git status --porcelain data/ public/data/ pipeline/source.json` empty —
still a byte-for-byte no-op. `npm run check` passes (lint, tests, `data:test`,
`data:check`, build).
