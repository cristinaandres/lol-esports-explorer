Fixed in 25f057a. `pipeline/refresh-data.sh` now rewrites `event-selection.json` and
`event-coverage.json` from the tag's `data/curated/*.jsonl`. Upstream publishes those
as JSONL and the pipeline reads a wrapper carrying the source, the pin date and a
note, so this is a regeneration rather than a `cp`. The pin date is kept when the tag
and the records are unchanged, so refreshing the current pin is a no-op; a real move
is stamped with the fetch date. `data/PROVENANCE.md` now says how the two files are
produced.

Verified by running `pipeline/refresh-data.sh v1.1.0`, the tag in
`pipeline/source.json` (commit 714ce6f): both files came back byte-identical to the
committed ones, `npm run data:build` rewrote no artifact and `npm run check` passed.

Refreshing also writes `data/upstream/manifest.json`, which is still not committed —
that remains TODO-04f6d9fb. The generated file was removed from the worktree
afterwards so `meta.json` does not hash a file git does not have.
