Fixed by splitting each of the four entity routes in two: an outer component that resolves the id against what it already loads, and an inner one that mounts the lazy hooks and is the rest of the page. Only `GameDetail` needed the game-level set to resolve (`useDataset()` + `useGameCorpus()`); the player, team and champion routes resolve from `useDataset()` alone.

Split points: `GameDetail` → `GamePage`, which mounts `useGameDetail()`; `PlayerDetail` → `PlayerPage` and `TeamDetail` → `TeamPage`, which mount `useGameCorpus()`, `usePlayerGames()` and `useAliases()`; `ChampionDetail` → `ChampionPage`, which mounts `useGames()`, `usePlayerGames()`, `useBans()` and `useAliases()`. The `useMemo` bodies moved into the inner components rather than being threaded through props; only the readiness guard and the id lookup came out of them. No shared helper was added, because one small inner component per route is the whole fix and a "data router" would outlive the ticket.

Measured in headless Chromium over CDP on the production build with the cache disabled. A bad id, before → after: `/games/1` requested the eager eight plus `games.json` and `matches.json` and then the four lazy files — 1,264,111 → 196,108 bytes, the game-level set remaining because that is what a game id is resolved against; `/players/nobody`, `/teams/nobody` and `/champions/nobody` requested their lazy sets — 954,790, 954,790 and 1,042,256 bytes → 49,007 bytes each, which is the eager set and nothing more. A real id requests exactly what it did before, and the rendered body text of all eight routes (found and not-found) is byte-identical before and after.

The failed branches stayed put: with one artifact refused, the player page still says "this player's games", the team page "this team's rosters", the champion page "the bans" and the game page "the game detail", each with Try again. One consequence worth knowing: a bad player, team or champion id now answers "not found" without waiting for the games, so a failing game-level artifact no longer turns a bad id into a failure block — nothing the not-found answer needed failed. `npm run check` green: lint silent, 214 tests, artifacts current, build green.
