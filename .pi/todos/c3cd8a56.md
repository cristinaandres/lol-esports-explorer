`/games/:game` calls `useGameDetail()` before it knows whether the id names a game, because hooks cannot be conditional. So an unknown id downloads the whole lazy set — `sides.json`, `picks.json`, `bans.json`, `player-games.json`, about 950 KB gzip — and then renders "No game called 1". The player page does the same with the player rows, and the champion page with the rows and the bans.

Measured: `/games/1` (no such game id) requested all four artifacts before saying the game does not exist; `/players/<bad id>` requested `player-games.json` before "No player with that id".

A shared, typo'd or truncated link costs a reader a megabyte to learn there is nothing there. The shape of the fix is a split: an outer component that waits for the eager dataset and resolves the id against it, and an inner component that mounts the lazy hooks only once the row exists. That is one extra component per route and it must not change what a found page renders.

Not urgent — the bytes are only paid by someone following a broken link — but it contradicts the payload budget the site states about itself.

Check: a not-found id requests no lazy artifact; a real id requests exactly what it requested before, and the rendered page is unchanged.
