## Done — docs/back-in-line

All four claims were checked against the code before being rewritten, and each was
true. Nothing under `src/` changed. `npm run check` passes: 196 tests, artifacts
current, production build green.

**AGENTS.md, "Current state".** `src/App.tsx` routes `/eras`, `/eras/:era`,
`/events`, `/events/:event`, `/events/:event/phases/:phase`, `/series/:series`,
`/games/:game`, `/players`, `/players/:player`, `/teams`, `/teams/:team`,
`/champions`, `/champions/:champion`, `/glossary` and `/selection`; `/compare` is
absent. Beyond phase 2 (`d25af0a`) and phase 3 (`ed6aa37`), two more shipped: the
3b polish round (`d5608c9`, `0d11519`, `4ba2b07`) and the 4b structure work
(`f07904d`, `0f9d4ee`). The paragraph now names the built pages and says phase 4
and the phase 5 design pass are not built. It does not repeat a phase count from
`docs/roadmap.md`, which still marks only phases 0–2 *(done)* — that is left for a
separate change and is listed below.

**docs/metric-definitions.md.** The code settles the false row: `TeamDetail.tsx`
renders `<Stat label="Win rate">` with `Ratio part={summary.wins}
total={summary.games}`, and the per-event table renders `Won` the same way. Win
rate is now a share, and the "deliberately absent" row is gone. The shipped metrics
left the planned table for the places the document already has: win rate, `Picked`
(`ChampionDetail.tsx`, picks over games) and `Presence` (picks plus bans over games)
are shares, both champion figures with a release-scoped denominator; KDA
(`career.ts`, `careerFrom`) got its own table because it divides by deaths, not by
a total the reader can check against the games; titles (`titles.ts`,
`championships`) became a count; the release date became a pinned fact
(`pipeline/sql/06_indexes.sql` `champion_releases`, joined in `pipeline/build.py`).
The planned table keeps only phase 4's head-to-head. CS and gold per minute were
never built — the player page divides by the rows that state the measure, per game
— so they joined the deliberately absent list, where gold per minute already was.

**Phase 2 and phase 3 specs.** Both status lines read "built and deployed", the
wording `2026-11-20-phase-1-era-detail.md` uses. Phase 2's test seams also named
two functions that never existed: `groupPicks` and `groupBans`; bans and picks are
two artifacts and `slotsFor` reads either. The seams now name `readDraftState`,
`slotsFor`, `sortSlots`, `slotSide` and `playersByRole` from `src/lib/draft.ts`.
Phase 3's `filterPlayerGames`, `summarise` and `deriveEra` are `appearancesFor`
(`src/lib/career.ts`), `careerFrom`/`careerFor`, and the `eras` field `careerFrom`
returns, which `PlayerDetail.tsx` renders as `mixed` when a selection spans more
than one era; `deriveEra` was never a function. The empty-filter fixture the old
sentence attributed to `career.ts` lives in `src/lib/filters.test.ts`, and the seams
now say so. Acceptance boxes were left unticked: every closed ticket in
`docs/specs/tickets/` carries `**Status:** done` and unticked boxes, so ticking
them here would invent a convention rather than follow one.

**docs/information-architecture.md.** `EventDetail.tsx` renders the teams and their
records, the event's own coverage, the series grouped by phase and the games with no
series. No leaders per role and no draft pool exist: `grep -rn "leader\|draft pool"
src` finds only a glossary sentence. Both the route-map line and the Level 2
paragraph were rewritten to what the page draws, and both "(next phase)" headings
were dropped. The component is `src/components/EmptyFilter.tsx`, used by the player
and team pages, so the table names it and describes the filter state it actually
covers.

  `games.json` became eager.
- AGENTS.md rule 2's example still says the era page "says where they open, rather
  than linking" — `EraDetail.tsx` links each event to its event page. The rule holds;
  the illustration is from before phase 2.

  `/compare` without saying phase 4 has not built it.
