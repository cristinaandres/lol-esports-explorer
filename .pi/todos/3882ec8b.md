**Source:** adversarial review of dev..main (2026-11-22).

**The claim.** "68 of the 1,140 players played two roles" appears in:
- `docs/metric-definitions.md`, the "Role (player)" row of Derived labels
- `pipeline/sql/06_indexes.sql`, the comment above `player_primary_role`
- `src/lib/types.ts`, the `Player.primary_role` doc comment

**What is true on the v1.2.0 pin** (verified with DuckDB):
players by distinct role count: 1 role = 1,072; 2 roles = 57; 3 roles = 8; 4 roles = 3.
So **68 played more than one role**, and only **57 played exactly two**.

**Fix.** Say "more than one" in all three places (the champion row already says "more than one", so this also makes the table consistent). Better still, state the rule and keep the counts in the test: prose should not carry a pin-specific number that rots on the next `refresh-data.sh`.

**Verify.** `uv run --project pipeline python -` with the role distribution query; grep for "two roles" returning nothing.
