`src/lib/data.ts` now has per-artifact cached loaders — `loadSides()`, `loadBans()`, `loadPicks()` beside the existing `loadPlayerGames()` — and `loadGameDetail()` composes the four instead of fetching them itself, so a game page reuses whatever a career or champion page already paid for. `useBans()` joins `usePlayerGames()` as the champions' seam.

`src/routes/ChampionDetail.tsx` asks for `usePlayerGames()` and `useBans()` and renders from the two when both are ready. Nothing else on the page reads a pick, so `sides.json` and `picks.json` are no longer requested.

Checked in headless Chromium against the production build (`vite preview`, CDP `Network.requestWillBeSent`), reading `data/` URLs per route:
- `/champions/ch-028a48ac2577` (Jarvan IV rendered): `player-games.json` and `bans.json` fetched; **`sides.json` and `picks.json` not fetched**. 236 KB gzip saved.
- `/games/1`: all four fetched — no regression on the page that actually draws a draft board.
- `/players/pl-000c8f0c1cd7` (MooJin rendered): `player-games.json` only, as `loader.test.ts` promises.

`src/lib/loader.test.ts` gains two cases at the seam the module already asserts: a champion page's two loaders cause exactly two requests and never the scoreboards or picks, and a game page asked afterwards fetches each shared artifact once. `npm run check` passes: lint, 198 tests, `data:check` current, production build.
