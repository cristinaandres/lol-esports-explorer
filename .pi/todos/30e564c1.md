`.github/workflows/deploy.yml` triggers on `push: branches: [main]` and `workflow_dispatch` only. There is no workflow on `pull_request`, so the 29-commit `dev` series that just landed was gated by whoever ran `npm run check` locally — the lint run, 216 tests, the 5 pipeline refusals, artifact freshness and the production build all on trust.

The check job itself is good: it runs exactly the five `npm run check` steps in the same order, plus Pages-only extras. It just never runs where review happens.

Fix: a workflow on `pull_request` targeting `dev` (and `main`) running the same steps, without the Pages permissions or the upload. Keep one definition if that is cheap — `deploy.yml` could share the check job through a reusable workflow rather than duplicating five steps that can drift apart; if duplication is simpler, say why.

Check: a pull request that breaks a test, a pipeline refusal, an artifact or the build turns red before it can be merged.
