`.github/workflows/deploy.yml` triggered on `push: branches: [main]` and
`workflow_dispatch` only, so `dev` was gated by whoever ran `npm run check`
locally.

**Changed.** The five steps moved, unchanged and in the same order, into a new
reusable workflow `.github/workflows/check.yml` (`workflow_call`), with the same
pins `deploy.yml` had: `actions/checkout@v4`, `actions/setup-node@v4` on Node 22
with `cache: npm`, `astral-sh/setup-uv@v5` on Python 3.12, then `npm ci`,
`npm run lint`, `npm run test`, the pipeline refusals, `build.py --check` and
`npm run build`. A new `.github/workflows/pull-request.yml` fires on
`pull_request` targeting `dev` or `main` and calls it with `contents: read`.
`deploy.yml` keeps its triggers, its `pages: write` / `id-token: write`
permissions and its Pages-only work — the 404 fallback and the artifact upload
now sit behind the `pages_artifact` input, which only the deploy sets. A PR run
therefore has no Pages scope and no deploy step, and `check.yml` declares no
permissions of its own because a called workflow can only narrow its caller's
token.

**Verified.** yaml-lint 1.7.0 and actionlint 1.7.7 are clean on all three files
(actionlint also clean on a whole-repo discovery run). Locally, in order: lint
clean; 232 vitest tests pass; 10 pipeline tests pass; `public/data is current
(16 files)`; `tsc -b && vite build` succeeds under
`BASE_PATH=/lol-esports-explorer/`, with the built `index.html` naming that path
in its asset URLs; `cp dist/index.html dist/404.html` succeeds.

**Not tested.** No GitHub Actions run was possible here, so the trigger matrix
and the called-workflow permission inheritance rest on the documented semantics
rather than on a green run. `BASE_PATH` is computed inside the shared workflow as
`/${{ github.event.repository.name }}/` — the caller's `github` context, which is
what deploy used before; the first real run should confirm it still resolves for
both `push` and `workflow_dispatch`. The ticket's "216 tests / 5 refusals" had
drifted: the suite is 232 tests and 10 pipeline tests.
