`src/lib/types.ts` declares `EventRow.blue_wins: number`, but `events.json` carries `null` for the two admitted events with no game: WCG 2011 and World Cyber Games 2013.

Nothing renders wrong today, and the reason is incidental: the event page passes it to `Ratio part={event.blue_wins} total={event.games}`, and `Ratio` prints an em dash when the total is zero, so the null is never formatted as a number. The type is still a lie, and a caller that trusted it — a sort, a sum, a `count(blue_wins)` — would produce `NaN` or throw on a game-less event.

The sibling fields were coalesced for exactly this reason when the era/event summaries gained `games_duration_stated` (event side: `coalesce(per_game.games_duration_stated, 0)`), so the fix is either the same coalesce in `pipeline/sql/03_events.sql` for `blue_wins` (and any other column with the same shape — check `red_wins`, `teams`, `players`, `series`), or an honest nullable type plus a caller that handles null.

Prefer coalescing and a non-null type: a count of blue-side wins over zero games is 0, not unknown, and the no-game events already state 0 for `games`.

Check: no field of `events.json` is null where the type says `number` — a data test asserting that for every numeric field of every row is cheap and prevents the next one.
