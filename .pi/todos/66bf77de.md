PageSkeleton, HomeSkeleton (src/routes/Home.tsx) and the inline two-block pulse in PlayerDetail and ChampionDetail are the same idea three times. The ticket promised one component with a few variants.

## Done — one skeleton, three shapes

`src/components/Skeleton.tsx` now owns every skeleton the ticket named;
`src/components/PageSkeleton.tsx` is deleted. One component, three shapes, each
the layout of a page that exists rather than a variant per route:

- `shape="page"` — breadcrumb, title, lead, six figure cells and two blocks. The
  ten routes that wait for their dataset, `PageSkeleton`'s old markup unchanged.
- `shape="cards"` — title, lead and the six-card grid. The home page, which waits
  for the same dataset but describes era cards, not figures.
- `shape="table"` — the h-24 summary strip and the table block. The player and
  champion pages, which render header and filters and then wait for the lazy
  artifact; the height is passed as `h-48` (player career) or `h-56` (champion
  record) because those two tables are not the same size.

Every shape now carries the `role="status"` / `aria-busy` / `aria-label="Loading"`
wrapper: the home page and the two inline blocks had none before and were read as
content. Loading and error branches in the routes are untouched; only the markup
returned changed.

Measured in headless Chromium against the production build, with data artifacts
held by CDP `Fetch.requestPaused` so the skeleton could be inspected at 1440x900:

| page | before | after |
| --- | --- | --- |
| home | 488 px, no status region | 488 px, same 9 divs, announced |
| player / champion before data | 608 px, 25 divs | identical markup |
| player after data | 96 px @ y=270 + 192 px @ y=378 | same blocks under a 300 px root |
| champion after data | 96 px @ y=382 + 224 px @ y=490 | same blocks under a 332 px root |

`npm run check` passes: oxlint (the one pre-existing EraGrid warning), 207 tests,
`data:check`, production build.

Left alone: `GameDetail`'s inline two-block pulse (h-40 then h-56, so the fixed
h-24 first block of `table` does not fit it) and `TeamDetail`'s two single blocks
are the same pattern but outside this ticket's list.
