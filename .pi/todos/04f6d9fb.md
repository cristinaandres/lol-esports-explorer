Three holes, all closed by making the pin's claims checkable rather than by softening the documents.

1. **The manifest is committed.** `data/upstream/manifest.json` is the upstream build manifest (`format: lol-dataset-provenance/1`, its `entities` and the wiki `payloads` behind them), fetched by the refresh script all along and never in the repository — so the sha256 in `pipeline/source.json` described a file nobody could compare. It is now in `data/upstream/`, and `pipeline/build.py` verifies its hash against the pin before rendering anything: missing, tampered or replaced without re-pinning stops the build with exit 1 and writes no artifact. Measured: a one-byte append gives `pinned: 872b43cf… / on disk: 7cc6942d…`; deleting the file names the refresh script.

2. **`meta.json` records every pinned file, not just the CSVs.** `modelFiles`/`upstreamFiles` were `*.csv` and `*.json` globs, which left `data-dictionary.md` unrecorded — and also `schema.sql`, which PROVENANCE never mentioned either. The rule is now the directory (`pinned_files()`), so anything pinned is hashed by definition: 14 model files and 6 upstream files, three more than before.

3. **The DDL is now re-pinned rather than hand-carried.** `data/model/schema.sql` came with the first commit and `refresh-data.sh` never copied it, so a re-pin would have left it stale. The script now copies it (and removes it first, like the CSVs and the dictionary), and re-running the refresh for the pinned tag proved the committed file is byte-identical to the tag's.

Also: `source.json`'s note said "the model CSVs"; it now says the CSVs, the dictionary and the DDL. The escaped backticks in PROVENANCE's champion-releases paragraph render as code now, and PROVENANCE states what the manifest can and cannot prove — it records sha256 per curated JSONL, while the two files pinned here are those records rewrapped, so it is the pin's receipts, not a second copy of the files.

Verified: two new tests in `src/lib/data.test.ts` (the manifest hash equals the pin's; the dictionary and the DDL are recorded), `npm run data:build` deterministic across runs, the refresh for the pinned tag a no-op for every data file, and `npm run check` green with 207 tests.
