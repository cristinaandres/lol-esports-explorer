A field-by-field audit of every artifact against `src/lib/types.ts` found declarations that the data contradicts:

| field | typed | reality |
|---|---|---|
| `DraftSlot.slot` | `number` | `null` on **3,821 rows** — 13.5% of all bans, exactly the bans of the 641 unordered-draft games |
| `Patch.patch` | `string` | a **number** on all 42 populated rows (`10.1`, `11.19`…), zero strings; one null |
| `Match.match_id/tab/date_time_utc` | `string` | null on the `match_key 0` placeholder row, which ships in `matches.json` |
| `EventRow.league` | `string` | null on WCG 2011 |
| `Player.player_id/overview_page`, `Team.team_id/overview_page/region`, `Champion.riot_key` | `string`/`number` | null on the placeholder rows and on 4 zero-game teams |

Nothing is proven user-visible, and that is the point: `sortSlots` sorts with `a.slot - b.slot`, which only "works" on null rows because JS coerces null to 0 — arithmetic that works by coincidence on data the type says cannot exist. `data.test.ts` already states the rule ("a null here is either a bug in the view or a lie in the type") and HEAD fixed exactly this class for `events.json`'s counts.

Fix per field: coalesce in SQL where a zero is honest, make the type nullable where absence is real (`slot` on an unordered draft is genuinely unknown, not 0), and correct `Patch.patch` to what the pipeline writes. Then add the test the ticket asks for: no field is null where the type says it cannot be.

Check: the audit script's table is empty, and `sortSlots` no longer depends on coercion.

## What changed

Each field was decided on what its absence means, and the decisions are recorded
in `src/lib/types.ts` where a reader meets them:

| field | decision | why |
| --- | --- | --- |
| `DraftSlot.slot` | `number \| null` | 3,821 bans of the 641 unordered-draft games have no recorded order. Slot 0 would be a claim the source never made. |
| `Patch.patch` | stays `string`; pipeline fixed | The DDL says TEXT and the dictionary says "as text; never padded or inferred". `read_csv` sniffed the column DOUBLE, so all 42 populated rows shipped as numbers under a string declaration. `dim_patch` now declares its three column types; `10.10` can no longer collapse onto 10.1. |
| `Match.match_id` / `tab` / `date_time_utc` | stay `string`; row not shipped | The nulls were the model's unknown member, never a series. |
| `EventRow.league` | `string \| null` | WCG 2011 states no league; `competition` already coalesces to 'Unknown'. |
| `Team.team_id`, `Player.player_id`, `Champion.champion_id` / `riot_key` | stay; row not shipped | The nulls were the unknown member rows. (`champion_id` was null on the same row and was missing from the ticket's table.) |
| `Team.overview_page` / `region` | `string \| null` | 4 zero-game teams. |
| `Player.overview_page` | `string \| null` | 39 players with no wiki overview page. |

`sortSlots` compared `a.slot - b.slot`, which read a null as 0; it now orders nulls
explicitly last and keeps `entry_index` (the order the source wrote them) as the
fallback. Two unit tests pin it.

The unknown-member rows (`*_key` 0) are not shipped in `matches.json`, `teams.json`,
`players.json`, `champions.json` or `patches.json` (the last through a new
`patch_rows` view). Checked first: nothing references key 0 as an entity — no game
names it as a side, no player row names it as a player, team or champion. The
sentinels on the facts stay (`match_key` 0 on 42 games, `patch_key` 0 on 279 games),
and every reader words them before consulting these files. Shipping the row was what
put null ids under string-typed columns and what made `teamPath(0)` build
`/teams/null`.

The invariant is executable in `src/lib/data.test.ts`: an explicit contract per
artifact, every field with a JSON kind, the complete nullable list stated once, and
a failure naming `file[row].field` for a null, a missing field or a wrong kind. The
table cannot drift from the types (a new field is a compile error) and cannot claim
a nullable field the type says is always there (also a compile error).

Artifacts regenerated with `npm run data:build`: five lose their key-0 row,
`patches.json` turns 42 labels into text, `meta.json` rehashes those six files.
Nothing else changed a byte.

## Verified

Audit before/after over every row of every artifact: 14 contradictions before
(`slot` 3,821 rows; `patch` 42 numbers + 1 null; `match_id`/`tab`/`date_time_utc`
1 each; `league` 1; `team_id` 1, `overview_page`/`region` 5; `player_id` 1,
`overview_page` 40; `champion_id`/`riot_key` 1 each), 0 after.

`npm run check` passes (17 test files, 226 tests, 5 pipeline tests, `data:check`
current, production build). Both new guards were shown red-capable: injecting a null
`patch` fails with `patches.json[1].patch: null`, and listing a non-nullable field as
nullable fails to compile.

Rendered check on the built site (`vite preview` + headless Chromium over CDP, HTTP
cache disabled, bundle `index-B7nP73gd.js`): byte-identical text before and after on
seven routes — the ordered draft board on `gm-0005e37fa1c8` (patch 26.09, slots 1-5
per side), the unordered one on `gm-006a86019276` (patch 5.7, bans in written order),
both a game and a series page printing "patch 10.19", a five-game series whose games
state no patch (em dashes), the Gragas champion page (banned 207/3,091), and
`/teams`.
