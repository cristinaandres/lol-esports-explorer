`champion_releases` joins `data/upstream/champion-releases.json` to `dim_champion` on the raw name, and 2 of its 173 rows join nothing: Akshan and Briar. A fold would not help — those names are simply absent from `dim_champion`.

This is the same silent-drop pattern the short-name join had before TODO-c78ec7cc: the row vanishes, the champion shows no release date, and nothing says the pin and the model disagree. The fix there was an `unmatched_*` view plus a build failure.

Decide which it is: a release date for a champion the corpus never fields (harmless, worth a comment and a test), or a drift between pin and model (a defect). Then either add `unmatched_releases` and fail the build on it, or record why the two rows are expected so the next reader does not have to rediscover them.

Check: `select count(*) from champion_releases anti join dim_champion on champion_name = name` returns the documented answer, and `npm run check` passes.
