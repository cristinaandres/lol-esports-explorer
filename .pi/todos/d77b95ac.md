The `prepared` memos on the four split routes can never dedupe: `useAsync` returns `{ ...state, retry }`, a new object identity on every render, and the memos depend on those objects (`PlayerDetail.tsx:106`, `ChampionDetail.tsx:81`, `TeamDetail.tsx:65`, `GameDetail.tsx:66`).

So every re-render recomputes `championships()` over 3,091 games, and on a career page `appearancesFor()` over 30,910 rows — once per keystroke in a filter box. Correctness is unaffected; the memo is decorative as written.

Fix at the source rather than at four call sites: either keep the hook's returned object stable between renders (`useMemo` around `{ ...state, retry }`, keyed on the state's own fields), or have the call sites depend on the primitive fields (`status`, `data`) instead of the object. The first is one change and protects every future consumer; say which and why.

Check: a profiler read, or a counter behind `championships`, shows the work happens when the data changes and not when a filter changes.
