Two tests pass for less than their names claim, so a real regression would stay green:

- **`src/lib/search.test.ts:92`** — "matches the middle of a name, ranked below a prefix" asserts only `expect(results.length).toBeGreaterThan(0)`. The fixture has no prefix match for `illum` (it matches inside "willump"), so the ranking half is never exercised; ranking `includes` above `prefix` would keep this test passing.
- **`src/lib/game.test.ts:60,77`** — `winnerKey` is compared against the inline restatement of itself, which is exactly how `01_semantic_views.sql` defines `blue_win`. That catches implementation drift, not a consistently-written wrong predicate. The independent witness already exists in the corpus: `sides.json`'s `is_winner` agrees with `games.blue_win` on 3,091/3,091 games, and the game page renders both — no test cross-checks them.

Fix: give the search test a fixture where a prefix match and a mid-word match both exist, and assert the order. Add a data test that walks `games.json` and `sides.json` together and asserts `winnerKey(game)` is the team whose side row says `is_winner`.

Check: flipping the prefix/includes rank order fails the first; returning the losing team from `winnerKey` fails the second.
