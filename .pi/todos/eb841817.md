`match_key` 0 is the model's placeholder match: `match_name` "Unknown", every other field null. A player reached through `?from=game:gm-00a3d746cd96` gets an arrival card whose series line reads "Unknown", which reads as a series called that rather than as a game that stands alone.

Either omit the line when the game has no series, or say it plainly ("no series recorded"), following the site's rule that absence is worded rather than dashed or faked. The card's other fields already distinguish stated from unstated, so the series line is the odd one out.

Check: the arrival card for a `match_key = 0` game states the absence, and a game with a real series still names it.

Fixed in 33d4093. The card now takes its label from `seriesLabel(matchKey, name)`
in `src/lib/format.ts`, which treats the placeholder key (and a missing or empty
name) as no name and returns "series not stated"; a real series name still loses
its date suffix through `stripDateSuffix`. That wording follows `measureWithUnit`
("gold not stated"), which the same card already uses for an unstated gold
figure, and the series list's "format not stated". The card's link to the game
and the " · Game N" suffix for multi-game series are unchanged. Unit tests pin
the wording beside `measureWithUnit`'s in `src/lib/format.test.ts`.

Verified with `npm run check` (211 tests, artifact check, production build) and
on the built site over CDP. Nyjacky's card from `gm-00a3d746cd96` read
"IPL 5 · Unknown" before and "IPL 5 · series not stated" after, still linking to
`/games/gm-00a3d746cd96`; Shushei's card from `gm-92e2d0ccd033` still reads
"Worlds Season 1 · Worlds Season 1 — Group Stage", and `gm-b6dc72a3f591` still
reads "… — Quarterfinals · Game 2".
