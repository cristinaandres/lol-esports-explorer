**Source:** complexity review, finding 1 (measured).

The eager set (fetched by every first page, `src/lib/data.ts`) grew from **46,526 → 59,784 bytes gzipped (+28%)** across the role/last-club work. Breakdown:
- `players.json` 27,687 → 40,076 gzip (+12.1 KB)
- `champions.json` 4,797 → 5,598 gzip (+0.8 KB)

Two columns do not earn their bytes:
- `primary_role_games` has **no consumer anywhere in `src/`** (grep) — the tickets' "so a reader can see the count" was never wired to a tooltip or cell.
- `last_game_date` is a full ISO timestamp whose only use is `.slice(0, 4)` for the year.

**Fix.**
- Drop `primary_role_games` from `champions.json` and `players.json` (keep the column in the SQL views, where the pipeline test uses it).
- Ship `last_game_year` (four characters) instead of `last_game_date`; keep the full timestamp in SQL.
- Update the contract in `src/lib/data.test.ts`, the types, the fixtures, and the `Primary role`/`Last club` rows in `docs/metric-definitions.md` if they mention the count.
- Correct `src/lib/data.ts`'s "~45 KB gzipped" comment to the measured figure (and keep it measured, not guessed).

**Verify.** `npm run data:build`, then compare gzip sizes before/after; `npm run check`; the index still sorts by role and shows `Zeus HLE 2026`.
