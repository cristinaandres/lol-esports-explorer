Both traps are closed in one change, because both are the same kind of bug: a figure or a string that is right on today's data and wrong the first time the data moves.

**The average with an invisible n.** `era_summary` and `event_summary` now carry `count(duration_seconds) as games_duration_stated` beside `avg_duration_seconds`. `count(expr)` skips NULLs, so it is exactly the row set `avg()` divides by rather than a second definition of it; the event view coalesces it to zero the way `games` and `series` already are, so an event with no game states 0. `ERA_FIELDS` in `build.py` carries the field through, since the era artifact is assembled by name. The era and event pages print it through `Stat`'s `hint` — "488 of 495 games state a length" — not through `Ratio`, because an average is not a share. `docs/metric-definitions.md` now states the rule, and a test in `src/lib/data.test.ts` sums the era counts and compares them to the games in `games.json` with a non-null duration, so widening the filter in the SQL fails there.

Measured: 3,084 of 3,091 games state a length; pre-herald 488 of 495; every other era all of its games (2,596 of 2,596); event counts sum to the same 3,084 with none above its game count (IEM Season 6 is the one short: 37 of 44). No average value changed. Read on the built site through `vite preview` and headless Chromium over CDP: `/eras/pre-herald` prints "488 of 495 games state a length", `/events/evt-00b7f5f0c357` prints "37 of 44 games state a length".

**The phase param decoded twice.** `PhaseDetail` dropped its `decodeURIComponent`: react-router already decodes the param, so on every tab in the corpus the second decode was a no-op and on a tab like "Day 1 (100%)" it would throw `URIError` inside the render. No corpus tab contains a percent sign, so the trap cannot be reproduced from real data; the case is pinned by a unit test in `src/lib/phases.test.ts` — `phaseSlug('Day 1 (100%)')` decodes back to the tab once, and decoding that result again throws — and the built site was opened on the synthetic URL `/events/evt-00b7f5f0c357/phases/Day%201%20(100%25)`, which now reaches the page as the tab text and renders the not-found view naming it, with no exception recorded.

Verified: `npm run check` green (lint silent, 216 tests, `public/data is current`, production build).
