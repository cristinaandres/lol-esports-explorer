On a champion's By-era table, a row where the champion was eligible but never picked shows the same fact twice, two ways: `Games 204 | Picked — | Banned — | Presence 0% (0/204) | Won —`.

`ChampionDetail.tsx` renders Picked and Banned as `presenceOf(era) === 0 ? '—' : count(...)` while Presence is a `Ratio(part=0, total=era.games)` that prints "0% (0/204)". An em dash means "not a measurement" everywhere else on the site (`format.ts` says so); here 0 *is* the measurement, and the row contradicts itself.

171 zero-era rows exist corpus-wide. Master Yi is the case to look at: picked 3, banned 1 in pre-herald, then four post-release eras with 204/186/203/678 games and no pick.

Fix: render a measured zero as 0 (or `0% (0/204)` on all three columns, consistently), and reserve the dash for an era the champion could not be played in — the distinction the page already draws with `presenceOf`. Check both readings of the page against the data for a champion that is picked everywhere, one picked once, and one never released in time.

## What changed

The guard was reading a result as an absence. `championRecord` drops games before
the champion's release date before it builds the era rows, so an era that ended
before it existed has no row at all — the page copy already said so. Every row the
table renders is an era the champion could be drafted in, denominated by the games
played in it after the release, so `picked` 0 and `banned` 0 there are measurements
of those games.

| column | eligible, never picked | before release |
|---|---|---|
| Picked | `0`, measured | no row |
| Banned | `0`, measured | no row |
| Presence | `0% (0/204)`, its denominator printed | no row |
| Won | `—`: no pick, so no denominator | no row |

`ChampionDetail.tsx` now renders Picked and Banned with `count(...)`, so the two
columns agree with Presence. Won keeps `Ratio(part=era.won, total=era.picked)` and
therefore its dash when there were no picks: a win rate over zero picks has no
denominator at all, which is the one place on these rows where the dash keeps its
meaning. The caption under `By era` states the rule, and the unreachable
`empty="not present"` override on Presence is gone — a row always has games, so it
never fired and only implied a case the table cannot render.

`presenceOf` and `ChampionEra` document that zero is measured, not missing, and
`docs/metric-definitions.md` records the zero-versus-dash rule next to the
champion shares. Two unit tests pin the distinction at the source: an eligible era
with no pick keeps its denominator (`games` 2, `picked` 0, `presenceOf` 0) instead
of vanishing, and a release date inside an era keeps that era while counting only
the games after it.

## Verified

`npm run check` passes (17 test files, 228 tests, 5 pipeline tests, `data:check`
current, production build).

Built site, `vite preview` and headless Chromium over CDP with the HTTP cache
disabled. Master Yi (`ch-ec9f120f445b`), before and after:

    Chemtech withdrawn | 204 | — | — | 0% (0/204) | —
    Chemtech withdrawn | 204 | 0 | 0 | 0% (0/204) | —

Shaco (`ch-1e31c331c8e3`), the single-pick shape, before and after:

    Before the Rift Herald | 495   | — | — | 0% (0/495)   | —
    Before the Rift Herald | 495   | 0 | 0 | 0% (0/495)   | —
    Elemental dragons      | 1,325 | 1 | 0 | 0% (1/1,325) | 0% (0/1)   (unchanged)

The shapes that must not change did not. Jarvan IV (`ch-028a48ac2577`) has no zero
row and renders exactly as before (`Atakhan | 678 | 160 | 150 | 46% (310/678) |
53% (85/160)`). Hwei (`ch-01ef89acfea0`), released 2023-12-05 mid-corpus, still
renders only its two eligible eras (Voidgrubs, Atakhan) — no pre-release era turned
into a row of zeroes.

A sweep of all 171 champion pages found 171 zero-presence rows — the same count
computed independently from `public/data` — each now `Picked 0 | Banned 0 |
Presence 0% (0/N) | Won —`, and no dash left in Picked or Banned on any page.
